ClassMesh Application Interactive Flowchart

  • ClassMesh Application Workflow
    • Application Startup
      • [System] start(Stage stage) method executes
        • Initialize Main UI Layout (BorderPane, TabPane, VBox for inputs, ScrollPanes)
        • Create UI Sections (using create...Section() methods)
          • School/College Information Section
          • Time Configuration Section
          • Semester Configuration Section
          • Teacher Configuration Section
          • Generate Timetable Button Section
        • Add UI Sections to main content VBox
        • Setup Main TabPane
          • "Input Details" Tab
          • "Generated Timetable" Tab
        • Set Initial UI Visibility (sections hidden, buttons disabled)
        • Create MenuBar
          • File Menu
            • "Load Configuration" Item
              • [User Action] Clicks "Load Configuration"
              • [System Action] handleLoadConfiguration()
                • Shows FileChooser for JSON
                • IF user selects file: Load JSON string, enable Generate, show Alert (UI not populated by this load)
                • ELSE: No action
                • CATCH Exception: Show Error Alert
            • "Save Configuration" Item (Commented out)
          • Help Menu
            • "About ClassMesh" Item → showAboutDialog()
        • Setup Scene and Show Stage
    • User Input and Configuration Workflow
      • 1. Institution Information Input
        • [User Action] Enters School/Department Names
      • 2. Time Configuration Input
        • [User Action] Sets time parameters, durations, constraints
        • [User Action] Clicks "Next -> Define Semesters"
        • [System Action] handleTimeConfigNextClick() → validateAndStoreTimeConfig()
          • IF Valid: Store config, show Semester Section, maybe buildSemesterSubjectGrid()
          • ELSE: Show Error Alert
      • 3. Semester Configuration Input
        • [User Action] Selects Number of Semesters
        • [System Action] (Listener) Calls buildSemesterSubjectGrid()
          • [Process] Reads old UI data, clears grid, rebuilds for new count
          • [Process] For each semester: Creates fields, sets subCountCombo.setOnAction (which builds subject fields, attempts pre-fill - known UI update issue here in user's Ver 1.2)
          • [Process] Pre-fills semester name/subject count from old data, triggering above onAction.
        • [User Action] Enters semester/subject details
        • [User Action] Clicks "Next -> Define Teachers"
        • [System Action] handleSemesterNextClick()
          • IF Valid: Rebuilds internal lists, shows Teacher Section, maybe populateTeacherMappingGrid()
          • ELSE: Show Error Alert
      • 4. Teacher Configuration Input
        • [User Action] Selects Number of Teachers
        • [System Action] (Listener) Calls populateTeacherMappingGrid()
          • [Process] Clears & rebuilds teacher input grid, sets onActions for subject assignment.
        • [User Action] Enters teacher details and assigns subjects.
        • [System Action] checkIfReadyToGenerate() → Shows/Hides Generate Button.
    • Timetable Generation
      • [User Action] Clicks "Generate Timetable"
      • [System Action] handleGenerateClick()
        • [Process] Validates Time & Teacher configs.
        • [System Action] Calls generateTimetableAlgorithmV2(...)
          • [Process] Main algorithm loop (Days → Slots → Semesters → Subjects)
          • [Process] Includes checks for: Post-Break Reset, Consecutive Subjects, Teacher Availability.
        • [System Action] displayTimetableGrid() (shows blank for empty slots)
        • [System Action] Switch to Timetable Tab, manage Export Buttons.
    • Export Timetable
      • [User Action] Clicks "Export to Excel" or "Export to PDF"
      • [System Action] Corresponding handleExport...() method
        • [Process] FileChooser, create document/workbook, write headers (School/Dept, Day/Sem, Time Slots), loop through data, write cells (empty for vacant), save.
    • Application Exit
      • [User Action] Closes window
      • [System Action] (No automatic state saving on exit in this code version) App terminates.
